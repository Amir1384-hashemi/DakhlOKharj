# چک‌لیست انتشار پولی ماشین حساب مهندسی

## انجام‌شده در کد
- [x] نام نمایشی در رابط Flutter و AndroidManifest به «ماشین حساب مهندسی» تغییر یافته است.
- [x] شماره نسخه نامزد انتشار 1.0.0+10 تعیین شده است.
- [x] مدل تجاری «خرید یک‌باره پیش از دانلود» انتخاب شده؛ هیچ پرداخت درون‌برنامه‌ای لازم نیست.
- [x] گردش کار QA و ساخت فایل آزمایشی محدوددسترسی بدون انتشار لینک APK عمومی تعریف شده است.
- [x] گردش کار تولید APK/AAB با کلید امضای مالک از طریق GitHub Secrets اضافه شده است.
- [x] در CI بررسی ریاضی، مقاطع، تیر و خرپا و آزمون صفحات انجام می‌شود.

## پیش‌نیازهای باقی‌مانده
- [ ] تعیین مبلغ فروش به تومان و تأیید نهایی صاحب برنامه
- [ ] تکمیل اطلاعات مالی/حقوقی حساب توسعه‌دهنده بازار و مایکت
- [ ] انتخاب package id معتبر و ثبت آن در پنل هر دو فروشگاه
- [ ] ساخت و نگهداری امن keystore اصلی (نباید در مخزن یا چت منتشر شود)
- [ ] افزودن چهار secret امضای انتشار به تنظیمات GitHub Actions
- [ ] اجرای workflow «Engineering Calculator | signed paid-store release»
- [ ] تأیید عملی نصب/اجرا روی گوشی واقعی، پایداری و مسیر به‌روزرسانی
- [ ] تست روی چند نسخه اندروید، اندازه‌های صفحه و حالت آفلاین
- [ ] اضافه‌کردن ایمیل واقعی پشتیبانی و سیاست حریم خصوصی صحیح/عمومی
- [ ] تهیه تصاویر واقعی فروشگاهی از برنامه (نه تصویر مفهومی)
- [ ] بررسی دسترسی‌ها، داده‌های کاربر و الزامات SDK هر فروشگاه
- [ ] آپلود خروجی امضاشده در بازار/مایکت، انتخاب **پولی قبل از دانلود**، ارسال برای بررسی و دریافت تأیید انتشار

**مهم:** فایل آزمایشی قدیمی که به‌صورت عمومی در GitHub منتشر شده است نباید به‌عنوان نسخه پولی معرفی شود. حذف آن از شاخه اصلی نیز همه نسخه‌های قابل دسترس یا نسخه‌های قبلاً دریافت‌شده را از بین نمی‌برد.

**iOS:** نیاز به macOS/Xcode، حساب Apple Developer و امضای جداگانه دارد؛ خروجی iOS در این workflow ساخته نمی‌شود.
